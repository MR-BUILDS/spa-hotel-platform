# Internationalization & Localization

## Initial locales

| Locale | Language | Direction | Role |
|---|---|---|---|
| `fa` | Persian | RTL | Default locale |
| `en` | English | LTR | International visitors |
| `tr` | Turkish | LTR | Regional visitors |

The locale list is configuration, not a hard-coded database constraint.

## URL strategy

Use locale-prefixed routes from the first public release:

- `/fa/...`
- `/en/...`
- `/tr/...`

The default Persian locale remains prefixed for consistent canonical and alternate-language URL handling. Configure `hreflang`, canonical URLs, localized sitemaps, and locale-aware metadata.

## Content model

- Store stable, locale-neutral identifiers and slugs separately from translated fields.
- Use translation tables for property, room, service, amenity, and destination editorial content.
- Missing translations must have a defined fallback policy; do not silently show a machine-translated string as verified editorial content.
- Admin content workflow should show translation completeness per locale.

## Formatting

- Use locale-aware number, date, and currency formatting.
- Keep stored timestamps in UTC and render in `Asia/Tehran` for Sarein venues.
- Persian UI must support correct RTL layout, Persian typography, punctuation, and input direction.
- Do not assume every user wants Persian numerals; number style should be a localization setting.
- Currency storage uses integer minor units and ISO currency code; display policy (rial/toman) requires business confirmation.

## Accessibility and layout

Use logical CSS properties (`margin-inline`, `padding-inline`, `inset-inline`) rather than left/right assumptions. Test navigation, forms, tables, calendars, and booking summaries in both RTL and LTR.
